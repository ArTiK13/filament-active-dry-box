# Параметрическая механика

Все размеры в миллиметрах. Z направлена вверх, стол Z=0, внешняя поверхность
стенки ящика Y=0, приставка Y>0, X вдоль длинной стенки. Требования и текущие
габариты — в [ТЗ](../docs/DESIGN_BRIEF.md).

## Исходники и параметры

- `drybox_cad/model.py` — детали и именованные сборки трёх состояний.
- `drybox_cad/parameters.py` — базовые значения, производные размеры и валидация.
- `parameters/default.json` — переопределения базовых значений; сейчас `{}`.
- `drybox_cad/templates.py` — шаблоны прокладок, вырезов и сверления, SVG/DXF.
- `drybox_cad/render.py` — изображения из точной геометрии.
- `drybox_cad/project.py` — пути и отпечатки исходников для отчёта.

Пример содержимого `parameters/default.json`:

```json
{
  "leg_spacing": 290,
  "journal_clearance": 0.55,
  "hex_clearance": 0.30
}
```

Не все размеры независимы: недопустимые сочетания отклоняет валидатор.
Для другой модели вентилятора или сервы меняется соответствующий построитель,
а не масштаб готового STL. Полный набор использованных параметров после сборки
записывается в `build/cad/parameters_resolved.json` от корня репозитория.

## Окружение

Проверено на macOS, Python 3.14.7, CadQuery 2.8.0, PyVista 0.49.1.
`requirements.lock.txt` — снимок проверенного окружения macOS, в том числе
платформенных пакетов PyObjC; установка этого файла на Linux/Windows не проверена.
Для текущей машины доступна общая изолированная среда
`/Users/xartik/3d_models/.venv`.

Для отдельной локальной среды на macOS, из корня репозитория:

```sh
python3.14 -m venv .venv
.venv/bin/python -m pip install -r cad/requirements.lock.txt
make build PYTHON=.venv/bin/python
```

## Сборка

Из корня репозитория:

```sh
make build PYTHON=/Users/xartik/3d_models/.venv/bin/python
make verify PYTHON=/Users/xartik/3d_models/.venv/bin/python
make package PYTHON=/Users/xartik/3d_models/.venv/bin/python
```

Вариант без графического контекста: `make geometry` с тем же `PYTHON`.
Рендеринг использует PyVista/VTK и требует доступного графического контекста.
Самостоятельные Python-точки входа также работают из любой текущей папки:

```sh
/Users/xartik/3d_models/.venv/bin/python /Users/xartik/3d_models/filament-active-dry-box/cad/build.py --no-render
```

Вывод всегда идёт в `build/cad/` данного репозитория, параметры читаются из
`cad/parameters/default.json`. Для повторного рендеринга после `make geometry`
выполните `make render`. Если CAD-исходники изменились, сначала нужна новая сборка.

## Результаты и проверки

| Путь от корня репозитория | Содержимое |
|---|---|
| `build/cad/exports/parts/` | STEP/STL 27 деталей устройства и двух пробников |
| `build/cad/exports/assemblies/` | Именованные STEP: dry, regenerate, cooling |
| `build/cad/exports/templates/` | 12 пар SVG/DXF в мм, масштабная линейка 100 мм |
| `build/cad/renders/` | Шесть видов геометрии |
| `build/cad/verification.json` | Результаты проверок, габариты, версии и SHA-256 исходников |
| `build/cad/print_manifest.json` | Количество экземпляров печатных деталей |
| `build/cad/parameters_resolved.json` | Все применённые параметры |
| `build/cad/artifact_manifest.json` | SHA-256 и размеры файлов последней упаковки |
| `dist/filament-active-dry-box-v1.zip` | Исходники, документация и результаты сборки |

Сборка проверяет валидность и отдельность тел, пересечения печатных деталей
в трёх состояниях, ход механизма на пяти углах, крайние варианты параметров,
отклонение недопустимых значений, STEP после повторного импорта, имена частей,
замкнутость STL и расхождение объёма сетки с BRep. Аудит дополнительно проверяет
единицы шаблонов, наличие экспортов и соответствие текущим исходникам.

`make geometry` не подтверждает актуальность оставшихся на диске изображений:
в новом отчёте список рендеров пуст. `make build` и `make render` записывают хеши
новых изображений, но не ставят отметки визуального просмотра автоматически.
Просмотр и фиксация его результата — отдельный шаг проверки поставки.
Архив содержит только изображения, перечисленные в текущем отчёте.

Иллюстрации в `docs/images/` — снимок прототипа для документации, не результат
последнего запуска. После изменения конструкции их следует обновлять только
после просмотра новых изображений.

Физические посадки, герметичность, момент приводов и тепловой режим не проверены.
Сначала печатайте `fit_coupon`, `test_journal` и один комплект заслонки;
упрощённые модели покупных компонентов печатать не нужно.

## Альтернативы механизма заслонок

`drybox_cad/retention.py` содержит две независимые версии и общий соосный привод
со свободным ходом. Настройки — `variants/spring.json` и `variants/magnetic.json`.
`build_variants.py` проверяет и экспортирует обе версии отдельно от базовой v1.
Команды: `make variants`, `variants-geometry`, `variants-render`, `variants-package`
с тем же `PYTHON=...`. Техническое описание — в
[VALVE_VARIANTS.md](../docs/VALVE_VARIANTS.md).
