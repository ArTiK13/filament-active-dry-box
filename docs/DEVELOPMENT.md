# Работа с репозиторием

## Постоянные ветки

- `main` — согласованные воспроизводимые снимки проекта. Первая версия является
  механическим прототипом; наличие в этой ветке не означает физических испытаний.
- `develop` — общая ветка текущей разработки, от неё начинаются новые задачи.

Первый коммит с организованным проектом общий для обеих веток. Основная ветка
репозитория на GitHub — `main`; локальная рабочая ветка после настройки — `develop`.

## Ветки задач

Создаются по мере работы, а не заранее:

| Префикс | Пример | Назначение |
|---|---|---|
| `cad/` | `cad/valve-retention` | Геометрия, приводы, параметры и CAD-инструменты |
| `electronics/` | `electronics/controller-schematic` | Схемы, платы и подбор электроники |
| `firmware/` | `firmware/control-states` | Прошивка, тесты, конфигурация контроллера |
| `docs/` | `docs/assembly-update` | Документация без изменения конструкции |
| `fix/` | `fix/template-units` | Исправление ошибки |

Обычный цикл:

```sh
git switch develop
git pull --ff-only
git switch -c cad/valve-retention
# Изменения и подходящие проверки.
git add cad docs
git commit -m "cad: add valve retention mechanism"
git push -u origin cad/valve-retention
```

Задача сливается в `develop` через pull request либо локально после проверки.
Ветки независимых задач не должны содержать посторонние изменения.
После объединения и проверки законченной итерации `develop` переносится в `main`.
При линейной истории:

```sh
git switch main
git merge --ff-only develop
git push origin main
git switch develop
```

Если fast-forward невозможен, сначала разберите расхождение веток;
не заменяйте историю через force push. Проверенный выпуск можно отметить тегом
`v0.1.0`, `v0.2.0` и т. п. Теги создаются при выпуске; физические испытания
описываются явно в заметках к выпуску.

## Содержимое коммитов

В Git хранятся CAD-исходники и наборы параметров, документация с иллюстрациями,
будущие схемы/платы и прошивка, файлы зависимостей и инструменты сборки.
Сгенерированные экспорты, отчёты, ZIP, окружения и локальные настройки исключены
через `.gitignore`. Архивы для печати можно прикладывать к выпускам GitHub.
Не добавляйте случайную лицензию: разрешение на распространение проекта
владелец выбирает отдельно.

Перед коммитом:

```sh
git diff --check
git diff --stat
git status --short
```

Для изменений CAD выполните `make geometry`, при изменении геометрии или вида —
также `make build` и просмотрите изображения. После просмотра обновите
`docs/images/` и относящиеся к изменению инструкции. Установка и команды —
в [CAD README](../cad/README.md).
